## Why

The current compatibility probe edits the caller's catalog, compiles only a Kotlin library and conflates a narrow success with permission to lift dependency ceilings. After the validated Toolchain 0.12.2 adoption, Mobi needs repeatable evidence for bridge upgrades and independent evidence for replacing that bridge.

## What Changes

- Add manual, source-bound compatibility plans using the existing executor and Kotlin resource ownership protocol.
- Rehearse a reviewed Kotlin/Metro/SKIE tuple in separate compile/link and full mobile profiles without adopting it.
- Assess supported SKIE integration and Swift export prerequisites against dated primary sources; run a bounded typed-facade experiment with the bridge unavailable in its owned copy.
- Record individual capability results, preserved native targets/tests, DI reachability, project changes, missing evidence and recovery outcomes.
- Leave the existing scheduled caller for slice 8; retain all production dependency pins, interop adapters and release defaults.

## Capabilities

### New Capabilities

- `compatibility-matrix-runner`: isolated bridge and direct-path assessments with conservative, source-bound capability results.

### Modified Capabilities

None.

## Impact

Repository-owned maintenance scripts, independent Kotlin adapter, contract tests, experiment fixtures and public English maintenance documentation. No mandatory external service, AI runtime, Elixir activation, dependency adoption or bridge retirement.
