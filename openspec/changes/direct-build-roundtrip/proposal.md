## Why

Slice 7 proved a bounded direct typed-facade simulator comparison, but it did not prove that a Kotlin implementation change reaches Swift with warm caches or that the original bridge can be restored and rebuilt. Slice 10 needs those independent receipts before an optional direct-default or retirement decision can advance.

## What Changes

- Add a manual `direct-roundtrip` profile using the existing baseline-first executor, owned resources and native jobs.
- In the isolated direct copy, test a small Kotlin value through Swift, change its implementation and native expectation without clearing caches, then require native tests and changed framework bytes.
- Validate every authored preimage before restoring baseline content and executable modes, remove experiment additions, clear owned generated products and rerun bridge native tests/build.
- Verify stage receipts and close only the bounded incremental and local rollback evidence gaps.
- Record a proposed transition ADR and the remaining release/device/lifecycle/onboarding/hosted gates. Preserve accepted ADRs 0003/0006 and the current production default.

## Capabilities

### New Capabilities

- `direct-build-roundtrip`: isolated incremental Kotlin-to-Swift validation and exact restoration to the retained bridge.

### Modified Capabilities

None.

## Impact

Repository-owned compatibility adapter, report verifier, temporary-repository contracts and public maintenance documentation. Toolchain 0.12.2 and the current Metro/bridge pins remain unchanged. No dependency adoption, default switch, bridge removal from the caller, workflow/schedule change, signing or publishing is included. Elixir remains dormant and independent.
